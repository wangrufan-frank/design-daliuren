# 十二天将布列设计

## 1. 目标

实现规则链第 5 阶段“天将排列”：依据林烽《大六壬详解》的贵人起例、昼夜贵人和顺逆布将规则，从有效日历与天地盘推导十二天将，形成可追溯、可重算校验的独立快照，并把同一份天将映射呈现在十二宫、四课和三传上。

本阶段完成后，阶段轨道推进到“课式生成”。

## 2. 规则来源与已确认口径

唯一规则来源为知识库笔记《六壬-遁干与贵人》，其原文来源标注为林烽《大六壬详解》第三章第二节。

已确认口径：

- 口诀所得贵人地支是贵人所乘的天盘支神，不是固定地盘宫；
- 必须在当前天地盘中查找该天盘支神所临的地盘宫，才得到贵人天将落宫；
- 卯、辰、巳、午、未、申时为昼占，用阳贵；
- 酉、戌、亥、子、丑、寅时为夜占，用阴贵；
- 贵人落亥、子、丑、寅、卯、辰六宫时顺布；
- 贵人落巳、午、未、申、酉、戌六宫时逆布；
- 本阶段不计算遁干。

## 3. 范围

### 3.1 本阶段包含

- 昼夜判定；
- 十干昼贵、夜贵查表；
- 贵人天盘支神到地盘宫的换算；
- 贵人顺逆判定；
- 十二天将完整布列；
- 十二宫、四课、三传的统一天将查询；
- 完整结构化证据；
- 独立天将快照、运行时守卫、会话失效接线；
- 天将审校界面、阶段返回导航与桌面/移动端测试。

### 3.2 本阶段不包含

- 旬遁；
- 天将五行、吉凶、所主事务或加临断语；
- 最终课式生成；
- 天将手工改写或人工批准；
- 旋转、布将动画或三维资源。

## 4. 架构选择

采用独立 `heavenly-generals` 快照，不把天将字段写回天地盘、四课或三传快照，也不在 React 中临时推导。

这样同一天将事实只保存一次：

```text
calendar ───────────────┐
                       ├─> heavenly-generals ─> course
heaven-earth ───────────┤
                       │
three-transmissions ───┘  流程前置，不读取其结果内容
```

`four-lessons` 通过 `three-transmissions` 构成传递上游。天将阶段运行器仍需验证完整的日历、天地盘、四课、三传链条，但快照的直接依赖元数据保持：

```ts
["calendar", "heaven-earth", "three-transmissions"]
```

四课与三传界面只使用天将结果提供的查询能力，不复制领域数据。

### 5.2 十二天将顺序

固定原序为：

```text
贵人 → 螣蛇 → 朱雀 → 六合 → 勾陈 → 青龙
     → 天空 → 白虎 → 太常 → 玄武 → 太阴 → 天后
```

顺布和逆布只改变地盘宫的推进方向，不改变该原序。

### 5.3 统一地支环序

领域层统一使用现有地支正序：

```text
子 → 丑 → 寅 → 卯 → 辰 → 巳 → 午 → 未 → 申 → 酉 → 戌 → 亥 → 子
```

- 顺布：索引每步加一；
- 逆布：索引每步减一；
- UI 方盘仍使用现有从巳宫起的视觉排列，但不得改变领域环序。

## 6. 计算流程

纯领域计算只接收已验证的日干、占时地支和天地盘。阶段运行器在调用纯计算前，额外要求有效四课与三传快照作为流程门禁；两者不进入天将算法参数。

1. 从日柱取日干，从已生效占时取占时地支。
2. 按占时地支判定昼占或夜占。
3. 按日干和昼夜查贵人表，得到贵人所乘天盘支神 `nobleHeaven`。
4. 在十二宫中查找唯一满足 `palace.heaven === nobleHeaven` 的宫位，其地盘支为 `nobleEarth`。
5. 按 `nobleEarth` 所属六宫判定顺布或逆布。
6. 从 `nobleEarth` 开始，按方向推进地支环序，把固定十二天将依次放入十二个地盘宫。
7. 每个宫位同时保存该宫的地盘支、天盘支神、天将和布列序号。
8. 由十二条宫位记录形成两个唯一查询：地盘宫到天将、天盘支神到天将。

若贵人天盘支神不存在、重复出现，或天地盘不是十二支唯一排列，立即失败，不做猜测性修复。

## 7. 领域结果

`HeavenlyGeneralsResult` 至少表达：

- `dayStem`：推导所用日干；
- `divinationHour`：推导所用占时地支；
- `dayNight`：`day` 或 `night`；
- `nobleHeaven`：贵人所乘天盘支神；
- `nobleEarth`：贵人所临地盘宫；
- `direction`：`forward` 或 `reverse`；
- `placements`：十二条唯一宫位记录；
- `evidence`：完整结构化证据。

每条 `placement` 包含：

- `order`：0 至 11；
- `general`：十二天将之一；
- `earth`：地盘宫；
- `heaven`：该宫天盘支神。

提供纯查询函数：

- 按地盘宫查询天将；
- 按天盘支神查询天将。

四课上神和三传支神都属于天盘支神，因此统一使用第二种查询，不修改原结果。

## 8. 证据契约

证据必须是具有稳定 ID 的判别联合，分为五个阶段：

1. `day-night`：占时支、昼夜集合和判定结果；
2. `noble-branch`：日干、昼夜类别、阳贵/阴贵表值和所选贵人支；
3. `noble-palace`：贵人天盘支、匹配宫位、地盘落宫；
4. `direction`：落宫、所属六宫集合和顺逆结果；
5. `placement`：布列序号、前一宫、当前宫、推进方向、天盘支和天将。

完整结果必须具有：

- 恰好一条昼夜证据；
- 恰好一条贵人查表证据；
- 恰好一条贵人落宫证据；
- 恰好一条顺逆证据；
- 恰好十二条布将证据；
- 唯一且稳定的证据 ID；
- 所有宫位记录到对应布将证据的闭合引用。

相同输入重复推导必须产生逐字节相同的结果与证据顺序。

## 9. 快照与运行时守卫

规则编号固定为以下版本化白名单值：

```text
heavenly-generals/lin-feng-noble-v1
```

守卫分两层：

1. 结构守卫检查枚举、精确字段、唯一性、数量、证据判别项和引用闭合；
2. canonical 守卫使用实际日历和天地盘重新推导结果，并逐项比对日干、占时、昼夜、贵人支、落宫、方向、十二宫布列和证据。

以下任一篡改都必须失败：

- 合法但错误的贵人支；
- 合法但错误的贵人落宫；
- 翻转顺逆方向；
- 调换两个天将；
- 重复、缺失或额外宫位；
- 宫位天地盘与上游不一致；
- 合法规则 ID 放在错误证据阶段；
- 证据字段存在但语义值错误；
- 证据 ID 重复或引用悬空。

## 10. 失败语义与失效范围

阶段运行器按真实上游顺序校验，失败后返回可通过 `validateSession` 的会话：

1. 日历无效：从 `calendar` 失效，清除全部快照；
2. 天地盘与日历不一致：从 `heaven-earth` 失效，仅保留有效日历；
3. 四课无效：从 `four-lessons` 失效，保留有效日历和天地盘；
4. 三传无效：从 `three-transmissions` 失效，保留有效日历、天地盘和四课；
5. 天将推导或结果校验失败：从 `heavenly-generals` 失效，保留全部有效上游；
6. 成功：先移除旧天将和课式，再写入新的天将快照。

错误采用稳定错误码，至少区分：上游缺失或无效、贵人支查表失败、贵人落宫不唯一、方向无效、布列不完整、结果守卫失败。

## 11. 审校界面

页面标题为“贵人起例 · 十二天将布列”。页面只消费已验证的天将结果及用于对照的上游快照，不自行计算规则。

### 11.1 信息顺序

1. 页首摘要：日干、占时、昼/夜贵、贵人所乘支神、贵人落宫、顺/逆布；
2. 十二宫方盘；
3. 四课乘将；
4. 三传乘将；
5. 完整证据。

### 11.2 十二宫方盘

- 沿用现有天地盘的十二宫视觉顺序；
- 每宫以天将为主信息，天盘支神和地盘宫为次信息；
- 贵人宫使用旧金色强调；
- 静态标记顺逆方向，不加入动画；
- 选择宫位后展示该宫的布将证据。

### 11.3 四课与三传

- 四课保持四、三、二、一的现有视觉顺序；
- 三传保持初、中、末的纵向顺序；
- 四课上神与三传支神都通过天盘支查询同一份天将结果；
- 替换既有“待天将加临”占位，不在原快照中增加可空天将字段。

### 11.4 可访问性与响应式

- 十二宫使用可键盘操作的按钮；
- 当前宫位公开 `aria-pressed`、`aria-expanded` 和证据区关联；
- 关闭证据后，焦点返回最后选择的宫位；首次直接关闭时回到初始宫位；
- 不提供人工改将或批准控件；
- 桌面端保持方盘为主视觉；
- 窄屏按“摘要、方盘、四课、三传、证据”单列排列；
- 页面无横向溢出，仍使用暗铜、汝窑青与旧金色视觉语言。

## 12. 应用接线

完整上游形成后，应用自动运行天将阶段：

- 成功时选择天将审校页，并把阶段轨道当前项推进到 `course`；
- 用户可返回历法、天地盘、四课、三传和天将等已完成阶段；
- 天将页只在 `isHeavenlyGeneralsResult` 和 canonical 上游匹配均通过时渲染；
- 失败消息归属于天将阶段，并继续允许回看仍有效的上游结果；
- 不创建伪造天将作为展示回退。

## 13. 测试矩阵

### 13.1 领域规则

- 十个日干的昼贵、夜贵共 20 组查表；
- 卯、申判昼，酉、寅判夜；
- 不同天地盘偏移下，贵人天盘支正确换算为地盘宫；
- 顺布和逆布各至少两个固定案例；
- 十二天将唯一、完整、顺序正确；
- 地盘宫查询和天盘支查询返回一致事实；
- 相同输入的结果和证据稳定。

### 13.2 守卫与会话

- 缺字段、错误枚举、重复宫位和非法数量；
- 贵人支、落宫、方向、任一天将或证据语义被篡改；
- 日历、天地盘、四课、三传任一真实上游缺失或失配；
- 每条失败路径只保留有效上游；
- 所有失败会话均可通过统一会话校验；
- 重算上游时清除旧天将和课式。

### 13.3 UI 与端到端

- 方盘十二宫完整，贵人宫突出；
- 四课与三传显示正确天将，不保留占位文本；
- 宫位选择、证据开闭、键盘焦点和 ARIA 状态正确；
- 390×844 移动端按批准顺序单列且无横向溢出；
- 离线状态下可从输入完整运行到天将；
- 有效天将产生后，阶段轨道推进到课式；
- 用户可返回所有已完成阶段而不触发重算。

## 14. 完成标准

本阶段只有同时满足以下条件才算完成：

- 林烽昼夜贵人表与顺逆规则全部固化为领域测试；
- 贵人必须经过天盘支到地盘宫的换算；
- 十二宫、四课、三传共享一份独立天将结果；
- 完整证据可审计且可被 canonical 守卫重算验证；
- 所有失败路径保留且仅保留有效上游；
- 天将审校页符合批准布局、键盘与移动端要求；
- 全量单元、集成、构建和端到端测试通过；
- 没有实现遁干、断语、课式或动画。
