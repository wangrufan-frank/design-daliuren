# 大六壬天地盘加临阶段设计

日期：2026-08-15  
状态：用户已确认

## 1. 目标

实现大六壬规则链的第 2 阶段“天地盘加临”：读取完整有效的历法与月将快照，按照“月将加临占时”的固定口径生成可追溯、可验证、可供下游消费的天地盘快照，并在应用中提供二维十二宫方盘审校界面。

本阶段的成功标准是：

- 天地盘计算只有一个领域事实来源，界面和下游不重复推导。
- 任意合法月将与占时都生成完整且一一对应的十二宫映射。
- 用户能从整盘或任一宫反向查看输入、规则和结论。
- 上游月将或占时变化后，本阶段及所有下游快照正确失效。
- 桌面端和移动端都能清晰审校天地盘。

本阶段不实现四课、三传、天将、三维模型、旋转动画、时间轴或天地盘独立人工修正。

## 2. 已确认规则口径

### 2.1 固定顺序

计算使用十二地支规范顺序：

```ts
["子", "丑", "寅", "卯", "辰", "巳", "午", "未", "申", "酉", "戌", "亥"]
```

地盘十二支固定不动。将有效月将放在有效占时所在的地盘宫，然后天盘十二支与地盘按相同次序顺布一周。不支持逆布、贵人顺逆或门派变体。

若 `M` 是月将下标、`H` 是占时下标、`E` 是某地盘支下标，则该宫天盘支下标为：

```ts
(M + E - H + 12) % 12
```

归一化转位数为：

```ts
(M - H + 12) % 12
```

该定义保证月将必定加临占时宫。

### 2.2 方盘方向

二维审校盘采用传统十二宫方盘：上南、下北、左东、右西。方盘外围按以下顺序布置固定地盘：

```text
巳 午 未 申
辰       酉
卯       戌
寅 丑 子 亥
```

界面中的天盘只改变各宫显示内容，不改变地盘宫位和方向。

### 2.3 修正规则

天地盘结果不接受独立人工修正。若用户对结果有异议，只能在上游修正月将或占时，随后重新计算天地盘。

若有效月将或有效占时来自人工修正，天地盘快照整体 `source` 为 `manual`；否则为 `automatic`。证据同时保留两个输入各自的来源。

## 3. 采用方案

采用“显式十二宫快照”。领域层计算并保存全部十二组 `{ earth, heaven }` 映射；二维盘、后续四课和未来三维盘只读取该快照。

未采用以下方案：

- 只保存转位数：会迫使界面和下游重复展开十二宫，破坏单一事实来源。
- 通用旋盘引擎：当前仅有固定十二支顺布，提前支持任意环数、方向或门派属于过度设计。

## 4. 数据模型

```ts
interface HeavenEarthInputValue {
  branch: EarthlyBranch;
  source: ValueSource;
}

interface HeavenEarthMonthGeneralInput extends HeavenEarthInputValue {
  name: MonthGeneralName;
}

interface HeavenEarthPalace {
  earth: EarthlyBranch;
  heaven: EarthlyBranch;
}

interface HeavenEarthEvidenceStep {
  ruleId: string;
  field: "plate" | `palace.${EarthlyBranch}`;
  input: string;
  conclusion: string;
}

interface HeavenEarthResult {
  monthGeneral: HeavenEarthMonthGeneralInput;
  divinationHour: HeavenEarthInputValue;
  offset: number;
  palaces: readonly HeavenEarthPalace[];
  evidence: readonly HeavenEarthEvidenceStep[];
}

type HeavenEarthSnapshot = RuleSnapshot<HeavenEarthResult, "heaven-earth">;
```

`palaces` 使用十二地支规范顺序存储，不使用方盘视觉顺序。方盘组件只负责把规范顺序映射到固定的视觉宫位。

快照元数据固定为：

- `stage`: `"heaven-earth"`
- `dependsOn`: `["calendar"]`
- `ruleId`: `"heaven-earth/month-general-over-hour-v1"`
- `source`: 两个有效输入均为自动值时是 `automatic`，否则是 `manual`

## 5. 组件与职责

### 5.1 `HeavenEarthPolicy`

- 接收有效月将和占时。
- 计算归一化转位数。
- 生成规范顺序的十二宫映射。
- 生成整盘证据和十二条单宫证据。
- 不读取 React 状态，不处理视觉方位，不修改上游数据。

### 5.2 `HeavenEarthSnapshotComposer`

- 只接受经过完整性校验的天地盘结果。
- 根据输入来源计算快照整体来源。
- 写入固定阶段、依赖和规则编号。
- 失败时不生成部分快照。

### 5.3 `HeavenEarthReview`

- 读取 `HeavenEarthResult` 并渲染十二宫方盘。
- 管理当前选中宫位，不执行排盘计算。
- 将选中宫位对应的现成证据交给证据栏。
- 提供桌面和移动布局以及键盘操作。

### 5.4 `RuleStageRail` 与应用编排

- 天地盘成功后将 `calendar` 和 `heaven-earth` 标为完成，当前阶段移至 `four-lessons`。
- 天地盘失败时停留在当前阶段，并显示结构化错误。
- 月将或占时变化时，沿现有依赖图移除 `heaven-earth` 及全部下游快照，然后重新运行本阶段。

## 6. 计算流程

1. 读取并验证 `calendar` 快照。
2. 读取月将和占时的有效值、名称与来源。
3. 验证两个地支均属于规范十二地支集合。
4. 计算转位数。
5. 遍历规范地盘顺序，计算每宫对应天盘支。
6. 验证地盘和天盘均各自包含十二个不重复地支。
7. 验证月将所在天盘支确实落在占时地盘宫。
8. 生成整盘与逐宫证据。
9. 生成不可变 `heaven-earth` 快照并写入会话。

## 7. 二维审校界面

### 7.1 桌面布局

沿用现有三列工作区：左侧起课输入、中间阶段审校、右侧推演依据。

中间区域顶部显示：

- `规则阶段 02 / 06`
- 月将名称与地支
- 占时地支
- 转位数
- 月将和占时各自的自动/人工来源

中央显示传统十二宫方盘。每宫以天盘支为大字、固定地盘支为小字。月将落宫使用旧金色强调，占时宫使用青铜色定位线；二者重合时同时保留两种语义，不新增第三种装饰状态。

方盘中央显示“月将名称与地支，加临占时地支”的摘要。结果计算完成后直接显示整盘，不播放动画。

点击或聚焦任一宫时，右侧证据栏显示：

- 有效月将与来源
- 有效占时与来源
- 该宫相对占时的顺布距离
- 对应天盘支
- “天盘某支加临地盘某支”的结论
- 规则编号

不提供拖动、旋转、逐宫编辑、批准按钮或时间轴。

### 7.2 移动布局

- 方盘保持正方形，不压缩为难读的小字。
- 证据在底部抽屉展开，关闭后焦点返回原宫位。
- 方盘下方提供十二宫双行文本对照作为窄屏和辅助技术的降级表达；它读取同一结果，不重新计算。
- 页面不得产生横向滚动。

### 7.3 可访问性

- 十二宫均可通过键盘到达，并有可见焦点。
- 键盘移动遵循方盘外围的传统宫序。
- 每宫读屏名称为“天盘某支加临地盘某支”。
- 选中宫位使用 `aria-current` 或等价的明确状态语义。
- 不仅依靠颜色区分月将落宫、占时宫和选中宫。

## 8. 错误处理

新增稳定错误代码：

- `INVALID_HEAVEN_EARTH_INPUT`：缺少有效 `calendar` 快照，或月将、占时不是合法地支。
- `HEAVEN_EARTH_RESULT_INCOMPLETE`：十二宫数量错误、地支重复、映射不是一一对应，或月将没有落在占时宫。

任一错误都不得生成部分快照，不得保留过期天地盘，也不得由界面猜测映射。错误显示输入摘要和失败原因，但不开放天地盘独立修正。

## 9. 规则案例

建立三类用户确认的回归案例：

### 9.1 同支案例

月将与占时相同。预期转位数为 `0`，十二宫全部为天盘支与地盘支同支。

### 9.2 相冲案例

沿用现有参考课例：月将胜光（午），占时子。预期转位数为 `6`，十二宫天盘支均与地盘支相冲；其中天盘午加临地盘子。

### 9.3 普通错位案例

使用已审阅历法案例 `2024-02-10T14:30:00`：月将神后（子），占时未。逐宫固化十二组预期映射，并确认天盘子加临地盘未。

## 10. 测试策略

### 10.1 领域测试

- 同支、相冲、普通错位三类案例逐宫断言十二组映射。
- 转位数始终归一化到 `0` 至 `11`。
- 非法月将、非法占时和不完整输入返回稳定错误。

### 10.2 全组合性质测试

遍历全部 `12 × 12` 月将与占时组合，验证：

- 结果恰好包含十二宫。
- 地盘支完整且不重复。
- 天盘支完整且不重复。
- 月将必定加临占时宫。
- 相邻地盘宫对应的天盘支保持相同顺序。

### 10.3 快照与依赖测试

- 阶段、依赖和规则编号固定正确。
- 输入来源正确传播到整体快照来源。
- 月将或占时变化后，天地盘及全部下游快照失效。
- 其他不影响历法有效结果的界面状态变化不使快照失效。

### 10.4 界面与浏览器测试

- 传统方位和十二宫内容正确。
- 月将落宫、占时宫、选中宫及重合状态可辨识。
- 单宫选择展示对应证据。
- 键盘操作、焦点恢复和读屏名称正确。
- 桌面和移动端无横向溢出。
- 移动端证据抽屉和双行文本对照可用。

## 11. 完成定义

- 三类规则案例和全部 `144` 种输入组合通过自动化测试。
- 单元测试、生产构建和浏览器测试通过。
- 真实 `calendar` 快照能稳定生成、验证并显示 `heaven-earth` 快照。
- 二维审校盘与证据栏只读取同一份天地盘结果。
- 上游修正能正确触发本阶段和所有下游失效与重算。
- 应用在本阶段结束时仍不计算四课、三传或天将。
