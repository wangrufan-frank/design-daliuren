# 大六壬四课生成阶段设计

日期：2026-08-16  
状态：用户已确认

## 1. 目标

实现规则链第 3 阶段“四课生成”：读取已生效的日柱与天地盘快照，按照传统固定寄宫和取上神规则生成可追溯、可校验、可供三传阶段直接消费的四课快照，并在应用中提供传统顺序的审校界面。

成功标准：

- 四课计算只有一个领域事实来源，界面与后续三传不重复推导。
- 内部结果固定按一、二、三、四课保存，界面固定按四、三、二、一课展示。
- 重复课体保留四个固定位置，不合并。
- 四课不能独立手工修改；上游变化会使本阶段及全部下游快照失效。
- 每课都能反查日柱、寄宫、所用地盘宫、天盘上神及规则版本。

本阶段不计算六亲、三传或天将。四课卡片只预留天将展示位置，待“天将加临”阶段完成后填入。

## 2. 已确认规则

### 2.1 固定寄宫

采用传统固定寄宫表：

| 日干 | 寄宫 |
| --- | --- |
| 甲 | 寅 |
| 乙 | 辰 |
| 丙、戊 | 巳 |
| 丁、己 | 未 |
| 庚 | 申 |
| 辛 | 戌 |
| 壬 | 亥 |
| 癸 | 丑 |

寄宫表是领域常量，不开放配置或逐课修改入口。

### 2.2 四课推导

设 `heavenAt(earth)` 表示读取天地盘中某个地盘宫所临的天盘地支：

1. 一课：下神为生效日干；取日干寄宫，以上神 `heavenAt(日干寄宫)`。
2. 二课：下神为一课上神；以上神 `heavenAt(一课上神)`。
3. 三课：下神为生效日支；以上神 `heavenAt(日支)`。
4. 四课：下神为三课上神；以上神 `heavenAt(三课上神)`。

每课同时记录实际查找的地盘宫。一课的下神是天干，但其查找宫是日干寄宫；二、三、四课的下神本身就是查找宫。

### 2.3 重复与修改

- 四课可能完全或部分重复；这是合法推导结果。
- 无论是否重复，都保留一、二、三、四课四个位置。
- 四课不接受局部手工修改。如结果有误，用户应回到上游修正日柱、月将或占时，再重新推导天地盘和四课。

### 2.4 参考案例

沿用现有历法与天地盘参考输入：生效日柱为辛酉，月将午加占时子，天地盘转位数为 `6`。按本设计预期四课为：

| 课次 | 下神 | 查找地盘宫 | 上神 |
| --- | --- | --- | --- |
| 一课 | 辛 | 戌（辛寄戌） | 辰 |
| 二课 | 辰 | 辰 | 戌 |
| 三课 | 酉 | 酉 | 卯 |
| 四课 | 卯 | 卯 | 酉 |

该案例同时验证日干寄宫、二课引用一课上神、三课取日支和四课引用三课上神。

## 3. 采用方案

采用独立“四课快照”方案。领域层生成标准结果并写入 `four-lessons` 快照，界面只负责展示，三传阶段只读取该快照。

不采用：

- 界面即时拼装：会失去稳定审计对象，并迫使后续阶段重复计算。
- 通用规则图：当前规则固定，引入通用节点与配置系统属于过度设计。

## 4. 数据模型

建议模型：

```ts
type FourLessonId = "first" | "second" | "third" | "fourth";
type FourLessonLabel = "一课" | "二课" | "三课" | "四课";

type FourLessonLower =
  | { kind: "stem"; value: HeavenlyStem }
  | { kind: "branch"; value: EarthlyBranch };

interface FourLesson {
  id: FourLessonId;
  label: FourLessonLabel;
  upper: EarthlyBranch;
  lower: FourLessonLower;
  lookupEarth: EarthlyBranch;
}

interface FourLessonsEvidenceStep {
  ruleId:
    | "four-lessons/stem-residence-v1"
    | "four-lessons/derive-v1";
  lesson: FourLessonId;
  input: string;
  lookupEarth: EarthlyBranch;
  conclusion: string;
}

interface FourLessonsResult {
  dayPillar: StemBranch;
  stemResidence: {
    stem: HeavenlyStem;
    earth: EarthlyBranch;
  };
  lessons: readonly [FourLesson, FourLesson, FourLesson, FourLesson];
  evidence: readonly FourLessonsEvidenceStep[];
}

type FourLessonsSnapshot = RuleSnapshot<FourLessonsResult, "four-lessons">;
```

`lessons` 的规范存储顺序固定为一、二、三、四课。传统视觉顺序由组件映射，不进入领域数据。

快照元数据：

- `stage`: `"four-lessons"`
- `dependsOn`: `["calendar", "heaven-earth"]`
- `ruleId`: `"four-lessons/derive-v1"`
- `source`: 日柱或天地盘任一有效输入含人工修正时为 `manual`，否则为 `automatic`

天将占位属于展示状态，不在本阶段结果中增加 `general: null` 一类伪数据。

## 5. 组件职责

### 5.1 领域策略

- 维护固定天干寄宫映射。
- 从规范天地盘快照读取 `heavenAt(earth)`。
- 按固定链路生成四课及证据。
- 不读取 React 状态，不决定视觉顺序，不计算六亲、三传或天将。

### 5.2 结果守卫与快照编排

- 输入端只接受有效的 `calendar` 和 `heaven-earth` 快照。
- 输出端验证四课的数量、顺序、课间引用和取值合法性。
- 成功时写入不可变 `four-lessons` 快照。
- 失败时不生成部分快照，并清除旧四课及全部下游快照。

### 5.3 四课审校视图

- 只读取 `FourLessonsResult`，不现场计算四课。
- 按四、三、二、一课渲染四张课卡。
- 管理当前选中课次和证据区焦点。
- 天将位置显示低权重的“待天将加临”，不伪造天将结果。

## 6. 校验与错误处理

计算前必须验证：

- 生效日柱由一个合法天干和一个合法地支组成。
- 日干能在固定寄宫表中唯一找到寄宫。
- 天地盘包含十二个规范地盘宫，每宫各有一个合法天盘地支。
- 天地盘通过第 2 阶段已有的规范性守卫，不接受页面临时拼装结果。

计算后必须验证：

- 恰好存在一、二、三、四课，且规范顺序正确。
- 所有上神都是合法地支。
- 一课下神等于生效日干，查找宫等于该日干寄宫。
- 二课下神等于一课上神，查找宫等于二课下神。
- 三课下神等于生效日支，查找宫等于三课下神。
- 四课下神等于三课上神，查找宫等于四课下神。
- 每课上神均等于天地盘中其查找宫所临的天盘地支。
- 不要求四课或课体唯一。

建议错误码：

- `INVALID_FOUR_LESSONS_INPUT`：缺少或无法验证上游快照，日柱非法，或日干无法寄宫。
- `FOUR_LESSONS_RESULT_INCOMPLETE`：课数、顺序、引用链或上神映射不符合规则。

失败时返回结构化错误和失效后的会话：保留有效的 `calendar` 与 `heaven-earth`，移除 `four-lessons` 以及所有依赖它的下游快照。界面显示失败原因，并提供返回历法或天地盘检查的入口，不开放四课编辑。

## 7. 证据设计

规则标识：

- `four-lessons/stem-residence-v1`：记录日干与固定寄宫。
- `four-lessons/derive-v1`：记录每课从下神或寄宫查得上神的过程。

每课证据至少包含课次、原始输入、实际查找的地盘宫、所得天盘上神和中文结论。

- 一课额外显示日干寄宫，例如“辛寄戌”。
- 二课明确显示“下神来自一课上神”。
- 三课明确显示“下神为生效日支”。
- 四课明确显示“下神来自三课上神”。

证据只描述已发生的推导，不包含尚未计算的天将或下游判断。

## 8. 界面与交互

四课区域位于十二宫方盘之后，阅读路径为“天地盘 → 四课”。

### 8.1 主视图

- 从左到右显示：四课、三课、二课、一课。
- 每张课卡自上而下显示：天将预留位、上神、下神、课次。
- 天将预留位统一显示“待天将加临”，视觉权重低于课体。
- 一课下神显示天干，其余下神显示地支。
- 重复课体仍按四张卡并列展示。
- 默认选中一课，使证据阅读从推导起点开始。

### 8.2 证据交互

- 点击或键盘选择任一课，显示该课的完整推导链。
- 证据区关闭后，焦点返回打开它的课卡。
- 提供“返回历法检查”和“查看天地盘”入口。
- 不提供课体编辑、拖动、合并或重新排序。

### 8.3 窄屏与可访问性

- 保持四、三、二、一课的传统顺序。
- 可使用横向滚动或四等分压缩，但单课内部始终保持纵向结构。
- 证据改为单列阅读，页面不得产生非预期的整体横向溢出。
- 四张课卡均可通过键盘到达，有可见焦点与明确选中语义。
- 读屏名称同时包含课次、上神和下神；天将占位不宣称已有天将结果。

## 9. 测试策略

### 9.1 领域规则

- 十天干全部映射到正确寄宫。
- 重点断言丙、戊同寄巳，丁、己同寄未。
- 使用已知日柱和天地盘逐课断言完整推导链。
- 二课严格引用一课上神，四课严格引用三课上神。
- 完全重复与部分重复课体仍保留四个位置。

### 9.2 守卫、快照与失效

- 非法日柱、缺宫、重宫和非规范天地盘均被拒绝。
- 篡改任一课的下神、查找宫或上神均被结果守卫拒绝。
- 阶段、依赖、规则编号和来源传播正确。
- 失败后只保留有效上游，清除四课及全部下游快照。

### 9.3 组件与浏览器

- DOM 顺序严格为四、三、二、一课；领域结果仍是一、二、三、四课。
- 每张卡都包含恰好四层有序内容：天将占位、上神、下神、课次。
- 默认选中一课，切换课次后展示对应证据。
- 关闭证据区后焦点返回触发课卡。
- 桌面端和窄屏均无非预期溢出，键盘操作和读屏名称正确。

### 9.4 完整验证

- 相关单元测试和组件测试通过。
- 全量测试通过。
- 生产构建通过。
- 桌面端、窄屏及关键键盘路径的浏览器回归通过。

## 10. 完成定义

- 真实的 `calendar` 与 `heaven-earth` 快照能够稳定生成、验证并保存 `four-lessons` 快照。
- 四课审校视图只读取领域结果，并按确认的传统顺序显示。
- 每课证据可完整解释寄宫和两次取上神链路。
- 上游改变或计算失败时，本阶段与全部下游正确失效。
- 本阶段结束时仍不计算六亲、三传或天将；天将仅显示为待后续阶段填充的界面占位。
